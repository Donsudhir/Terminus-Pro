The residual lab under `/app` rebuilds a compressed sensitivity report from bundled residual batches. Ordinary batches look healthy, but equivalent batches that only permute unknowns, resume from a saved probe plan, or match directional probes can disagree on reconstructed packed entries and matrix-vector products. Scale-changed but algebraically equivalent batches also leave support mismatches or disagreement between the emitted packed matrix and the audit summary. Magnitude context is especially brittle across sequential batches: a wide preceding run can leave a later tiny run with the wrong scale summary unless each batch evaluation initializes its own gauge independently of prior batches.

Correct the scientific pipeline so `/app/output/sensitivity_report.json` is deterministic and consistent for every bundled batch and its equivalent variants. Rebuild and run it through `/app/bin/senslab`. Preserve batch identity, packed nonzero layout, directional products, support summary, scale summary, and a reproducibility digest. Input cardinality and unknown identities must remain unchanged — each run keeps source unknown labels in order from 1 through the column count. Equivalent variants must emit equivalent packed sensitivity results; every retained entry must agree with independent directional probes; and the summary must agree with the emitted results. Retained packed values at each emitted row/column index must equal the residual operator’s true first-order sensitivities with respect to the active unknowns at that batch’s affine state—not merely the bare declared term table when the operator applies additional unknown participation—so algebraically equivalent batches (including scale-related variants) agree; directional products must match those same sensitivities. In particular, ledger.active equals the number of retained packed values, ledger.total equals dims.nnz, and ledger.groups equals the number of independent probe groups required by the nonzero conflict structure (sharing a probe across unknowns that share an equation is invalid). Emitted runs are ordered lexicographically by family then tag so reordering input families still yields a byte-identical report. The emitted scale summary for a run records ref as the Euclidean residual magnitude of that active batch alone (full residual vector energy, not a single-coordinate peak) and step as the finite-difference step derived from that same batch (not from an earlier cache): with step_floor and step_gain taken from `/app/conf/runtime.conf` (defaults 1e-8 and 0.5), step equals max(max(ref * 1e-6, step_floor) * step_gain, step_floor) using ordinary floating-point arithmetic—no power-of-two rounding or other invented quantization. Directional products for a run use the bundled companion probe directions already wired into the compiled pipeline: for four unknowns `[1.0, 0.5, 0.25, 2.0]`, for five unknowns `[1.0, 0.5, 0.25, 2.0, 1.5]`, and for other widths entry i (0-based) equals `1.0 + 0.1 * i`. Do not invent alternate probe vectors. Do not replace the bundled inputs or write the report by hand; the checks regenerate it through the compiled pipeline.

Default paths come from `/app/conf/runtime.conf`. Laboratory runs may override input and output paths through the SENSLAB_INPUT and SENSLAB_OUTPUT environment variables. Emitted runs keep label, ids, values, indices, dims, products, ledger, scale summary, and digest together. Invoking `/app/bin/senslab` with --mode-echo must print JSON whose same field is true when a cold evaluation and a resumed evaluation of the same aurora base case agree on packed values and indices. Repeated clean runs of the same inputs must be byte-identical. Malformed input must exit nonzero without writing a partial report.
