# Common Mistakes Ledger

Living prevention list for Snorkel / Terminal-Bench task work. Read this at the
start of every task chat (with the board) and before every package or upload.
When a new platform rejection or local gate surprise appears, append a row here
and a matching `FAILURE-*` node in `KNOWLEDGE_GRAPH.md`.

Do not delete entries. Mark `Status` as `prevented` when a mechanical check or
ADR closes the hole; keep the symptom text so later chats still recognize it.

## How to use

1. **Before packaging / upload** — walk the Prevention checklist for every
   `active` or `recurring` entry that applies to the task type.
2. **After platform feedback** — if the rejection matches an existing ID, bump
   `Seen` and link the submission. If it is new, add a row + knowledge-graph
   node in the same session.
3. **When adding a mechanical gate** — set `Status` to `prevented` and name the
   enforcing command or check id in `Prevention`.

## Pre-upload checklist (copy into Step 4 notes)

- [ ] Final Dockerfile layer still runs `asciinema --version` (and `tmux -V` if installed).
- [ ] No `ln -sf …/python3.X /usr/bin/python3` after Debian `asciinema` / `tmux` apt install.
- [ ] Every test-invoked CLI flag and env override appears in `instruction.md` as a contract, or the flag was renamed and both code + instruction agree.
- [ ] Conservatism / fail-closed / byte-stability behaviors that tests assert are stated as symptoms or contracts, not as silent test-only rules.
- [ ] Reward=1 is impossible without the core pipeline (no ELF/string-only proxies for the main claim; no untested instruction requirements) — CM-006.
- [ ] Rubric is output-based and domain-correct (no process-only or off-domain criteria) — CM-006.
- [ ] UI rubric paste is `Agent …, ±N` (score last), ≥3 negatives, mixed severity (±5/±3/±1–2), positives sum 10–40 — CM-015 / `TASK_PROPOSAL_RUBRIC.md`.
- [ ] `test.sh` writes `echo 0 > /logs/verifier/reward.txt` immediately after `mkdir -p /logs/verifier` — CM-016.
- [ ] Apt toolchain packages (Go/compilers) are not brittle exact pins; use unpinned distro package, builder-stage copy, or checksum snapshot — CM-017.
- [ ] `test.sh` does not run `python -m pytest` from an agent-writable cwd; uses `cd /tests`, `--confcutdir=/tests`, and `PYTHONSAFEPATH=1` (or `-P`/`-I` / non-root) — CM-007.
- [ ] Planted `/app/pytest.py` and `/conftest.py` shadow probes still fail the verifier — CM-007.
- [ ] Series/probe tests reject always-refine-only and still require cancellation conservatism — CM-008.
- [ ] Bug loci are not scream-sticky / one-glance `if a < 0` after named probes exist — CM-008.
- [ ] New task agent-facing languages are not Python-primary (ADR-0014 / CM-011); Snorkel Language label matches the niche stack.
- [ ] Docker CI parity passes: sanctioned final image, context size, dependency pins/locks, unsafe capabilities/reserved mounts, reproducible downloads, and offline verifier setup — ADR-0020.
- [ ] Warning families reviewed: layer volatility, unnecessary runtime build tools, and archive extraction/removal — ADR-0020.
- [ ] Current upstream pre-submission result explicitly passes delegated `typos` and `check_task_sizes`; local approval does not infer them — ADR-0020.
- [ ] `collapse_check.py` has no FAIL; every WARN has a Step 3b justification file.
- [ ] Fresh oracle 1x = 1.0, NOP = 0.0, Step 4 oracle 10x = 10/10 with job paths recorded.
- [ ] `docker network create` probe succeeds before starting 10x; cleanup script run after.
- [ ] Platform feedback ingested; board `next_action` matches the _current_ rejection mode.
- [ ] Every JSON key and exact output filename the tests assert is named in `instruction.md` or a normative schema doc it cites; do not rely on lagging format notes — CM-018.
- [ ] Marker / domain / counter semantics are stated as observable contracts without fixture-specific expected tallies (no answer-shaped numbers) — CM-018 / CM-002.
- [ ] After upload: if revision notes say AutoEval FAILED but difficulty/artifact are empty, diagnose CM-019 (env build) before CM-008 hardness edits; confirm Fast static PASS.
- [ ] Current reviewed model and eligibility snapshot is enforced (Slices 3–4); automated live-source diff/promotion remains pending — CM-020.
- [x] `test.sh` current `rc=$?` / captured-status / no-trailing-exit contract is mechanically enforced — CM-021.
- [x] No net-new blocked category, milestone, or UI work; exempt in-flight structure is mechanically checked against the current official layout — CM-020/022.
- [x] Canonical roots and generated status views agree, both archive indexes are current, and the repository regression suite is green — CM-023.

## Adding a new mistake

```text
1. Append a CM-00N row with Status=active, Seen=<submission or job>, Symptom, Root cause, Prevention.
2. Add FAILURE-CM-00N (or reuse FAILURE-*) + edges in KNOWLEDGE_GRAPH.md.
3. If a mechanical check exists or was added, set Status=prevented and name it.
4. Mention the ID in sudhir_logs/CHANGELOG.md for that session.
```
