# REV-6 reviewer feedback — robust-predicate-scale-parity

Source: Snorkel submission fcee6e2e-1c89-476f-aa10-5932a474ef97 (2026-07-19)

This is a concrete, reproducible grading-integrity hole in test.sh, separate from any difficulty question — the cross-language pipeline itself is well-built and solvable. But as written the verifier can be made to report reward=1 without the geometry pipeline running at all, so it has to be closed before this can pass.

The blocker (verifier bypass). The Dockerfile sets no USER, so the agent runs as root, and WORKDIR is /app — the directory the task tells the agent to edit and rebuild (host/*.rs, native/*.c, analysis/*.f90). test.sh does not cd and runs `python -m pytest ... /tests/test_outputs.py` from that cwd. `python -m pytest` puts the current directory first on sys.path, so a submission can drop `/app/pytest.py` containing `import sys; sys.exit(0)`; the `pytest` import resolves to that shadow module and the process exits 0 before any test is collected, after which test.sh writes reward=1 with `/app/bin/geomlab` never built or run. I reproduced it on the bundle's exact pytest (8.4.1): baseline with a real failing test gives rc=1; with `/app/pytest.py` planted the same command gives rc=0. The `verifier-python` wrapper does not help — it just execs `/opt/verifier/bin/python` with no `-P`/`-I`/`PYTHONSAFEPATH`, and PATH puts `/opt/verifier/bin` first anyway, so the shadow is live either way. A secondary exposure exists from the same root-agent surface: because cwd is /app and the testpath is /tests, pytest's rootdir can resolve to `/`, where a root agent can also plant `/conftest.py` = `sys.exit(0)`.

Fix (verified). Keep the working directory off sys.path and confine conftest discovery to the test tree. I verified in a root chroot, with both `/app/pytest.py` and `/conftest.py` planted, that `cd /tests` plus `--confcutdir=/tests` on the pytest command returns rc=1 (attack neutralized), while a genuinely failing test still returns rc=1 and a genuinely passing test returns rc=0 — so it does not just always-fail. `PYTHONSAFEPATH=1` (or `-I`/`-P`) closes the sys.path shadow specifically; combine it with `--confcutdir=/tests`, or run pytest as a non-root user, to also neutralize the `/conftest.py` vector. Any of those closes it; the `cd /tests` + `--confcutdir=/tests` pair is the one I confirmed end to end.

Non-blocking notes (from the current run and the prior reviewer, worth folding in while you revise). task.toml declares difficulty = "hard" but the latest measurement is MEDIUM (opus 5/5, gpt5 3/5, oracle 3/3, nop 0/1, solvable) — this is a Rust/C/Fortran task, not Python, so medium is a perfectly fine level and this is only a label alignment, not a defect. task.toml also carries an `mcp_servers` key that isn't part of the schema. And a couple of rubric lines grade process ("traces the numerical decision path", "reproduces the divergence before changing code") rather than the output artifact; those are fine to keep but tend to be weaker discriminators than output-based criteria.

The cross-language failure chain — conservative magnitude bound escalating uncertain signs to exact refinement, per-batch scale reconstruction, orientation-preserving connectivity, and a strict alternate build — is genuinely well-constructed and the corpus/report protections look solid. Close the pytest cwd-shadow (and the `/conftest.py` rootdir vector) and this is in good shape.
