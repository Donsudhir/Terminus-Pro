The scientific mesh lab under `/app` advances a bundled case that checkpoints mid-run, remeshes, then resumes. Residual norms and iteration counts can look plausible on that path, but solution-field digests diverge from a never-interrupted twin on the same case. Pointwise residual samples can also diverge from that twin while still looking numerically ordinary. Fresh runs without a checkpoint remain correct and must stay byte-stable across clean rebuilds.

Correct the pipeline so interrupted and uninterrupted trajectories produce identical solution-field digests and residual contracts, and so the healthy no-checkpoint control stays byte-identical under clean paired evaluation. Rebuild and invoke `/app/bin/meshlab`. Emit `/app/output/parity_report.json`. Do not replace the bundled inputs or write the report by hand; the checks regenerate it through the compiled pipeline.

Default input and output paths come from `/app/conf/runtime.conf`. Laboratory runs may override them with the `MESHLAB_INPUT` and `MESHLAB_OUTPUT` environment variables. Repeated clean runs of the same inputs must be byte-identical. Malformed input must exit nonzero without writing a partial report.

`/app/docs/parity-report-schema.md` is the normative schema for `/app/output/parity_report.json`. Graded fields include schema_version, runs, family, tag, mode, field_digest, samples, residual_samples, residual_norm, iterations, reuse_mark, geometry_token, fold_order, summary, twin_agree, control_stable, digest_match, and digest. Exact fold and reproducibility digest algorithms live only in that schema document.
